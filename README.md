# Kalshi_Prod — C++20 port of the Kalshi quoting engine

A production C++ port of the live trading path of [**Kalshi**](https://github.com/arjankang4/Kalshi)
(the Python SPX/NDX market maker): everything `strategy/run_04_quote_loop.py` reaches — option-board
pricing, the smile fit, the hourly variance calendar, dollar Greeks and the edge curve, ladder and
requote logic, risk limits, the Kalshi and Massive clients (libcurl HTTP, a hand-rolled RFC 6455
WebSocket over OpenSSL, RSA-PSS signing) and the journal.

The bar is **bit-identical output**. Not "close" -- the same inputs must produce the same theo,
the same R, the same ladder, the same orders, the same journal bytes, down to the last double. The
Python is the **reference oracle**; golden vectors are generated by driving a FROZEN copy of it
(see "Pinning the reference"), and a replay gate runs both engines through scripted sessions and
diffs every decision.

    make check      # regenerate vectors from the pinned Python, build, run all suites, lint
    make parity     # end to end: the Python run_04.cycle and kp::app::cycle over 3 scripted
                    # sessions, every decision / order / journal row / log line compared exactly

Sibling repos: [Kalshi](https://github.com/arjankang4/Kalshi) (the Python reference) and
[Kalshi_BTC](https://github.com/arjankang4/Kalshi_BTC) (the BTC quoter).

> **What is not published.** The fitted model artifacts the engine reads at runtime, the research,
> the datasets and the live tuned parameters are private. Constants here mirror the public Python's
> **illustrative** values. `make build` and the self-contained unit suites run from a clean clone;
> `make vectors` / `make parity` also need the model artifacts under `KALSHI_ROOT` and the recorded
> WebSocket fixtures under `tests/fixtures/`.

## Status (2026-09-23)

**Everything on the live path is ported**, and both gates are green:

- `make check`: 53 suites over 4.1M golden vectors (~630 MB, regenerated not committed), each suite mutation-tested (a deliberate break of
  the C++ was confirmed to turn it red; the few mutations that stayed green are recorded in the
  commit that met them, with why).
- `make parity`: 3 sessions x 120 cycles (fast-spot; REST-index + delta-adjust; live against a
  fake exchange with partial rejects, 429s, not_found cancels and fills), SPX + NDX, 4pm + hourly
  boards, the realized-vol lean on -- ~10k orders and ~32k journal rows per run, 360/360 cycles
  identical including stderr. Dropping one step of the cycle (re-price-at-send) turns 94 of 120
  cycles red.

| layer | modules |
|---|---|
| pricing | bs, theo_core, pricer, skew, atmvol, varcal (reader), gapcal (reader), edge, greeks, spot, universe, hourly, lean, basis, validate_theo (the cycle's pricing entry) |
| rvol (live half) | features, model, live -- incl. numpy's own arithmetic (SVML log, pairwise sum, OpenBLAS FMA dot) |
| strategy | quoting, band, risklimit (+ account-equity mark, AccountPoller), edgemgr, skewstate, leanchain, deltaadj, orders, budget, fastcancel, journal, risktape, cancel_all |
| I/O | net (libcurl HTTP, hand-rolled RFC 6455 over OpenSSL), kalshi (client + RSA-PSS signing, MarketFeed), massive (REST, QuoteCollector, index, futures, history, streams), storage (feed_tee + segments, book, units) |
| app | `kp::app::cycle` (= run_04.cycle, all I/O behind `CycleIO`), build_desired, verdict and helpers |

**What it has and has not done live.** It has never sent an order. `quote_loop --live` and
`cancel_all` both refuse unless `KP_ALLOW_LIVE=1` is also set -- a second switch on top of the
reference's, until someone decides otherwise. Dry runs against the real feeds on 2026-09-23
matched the Python line for line through startup, and both engines then stopped at the same
place: the market-data vendor account had lost its WebSocket and index entitlements, so
`col.start()` raises in both. Until that is restored neither engine can quote; nothing in either
codebase is at fault.

**Deliberately outside the replay gate** (unit-vector tested only): the fast guard's thread
(timing-driven), and the socket pumps themselves (their frame-handling state machines are
vector-tested against the Python on real frames).

**Not ported, on purpose:** everything offline -- storage's S3 half, backtest/, notebooks, the
edgecal / rvol / varcal / gapcal fitters, study_* / validate_* scripts, pricing/{fees,eventcal,
varbars}, strategy/latency*. The C++ reads their artifacts from `--kalshi-root`.

## Pinning the reference

The Python keeps moving, so the port is tested against a frozen copy of its CODE:
`ref/py-<stamp>/` (gitignored), with `ref/current` pointing at the one in force. Model artifacts
and secrets are read-only symlinks into the live tree, and `var/journal`, `var/risk` and `data/ws`
are real directories inside the snapshot, so running the reference from it never writes into the
Python checkout.

To take up newer Python: `tools/snapshot_ref.sh <path to Kalshi>` takes a new snapshot and points
`ref/current` at it; then `make config && make check && make parity`, and port whatever goes red.
`config_fresh` fails on any config constant that moved; `vectors_fresh` on any vector taken from
a source that changed.

## Running it

    build/apps/quote_loop --minutes 5 --out-root /tmp/qlrun      # dry: plans every order, sends none
    KP_ALLOW_LIVE=1 build/apps/quote_loop --minutes 30 --live     # the reference's --live, twice

Same flags as `run_04` (`--no-ws`, `--no-fast-spot`, `--no-delta-adj`, `--no-guard`, ...), plus
`--kalshi-root` (where secrets and models are READ) and `--out-root` (where journals, tapes and the
opening-equity file are WRITTEN; default the Python tree, as production wants -- point it elsewhere
for any test run, because the storage timers ship `data/ws` to S3). Massive permits ONE options
socket per account: never run it beside a Python `run_04`, and not in the 09:30-09:50 ET dry-run
window.

## Rules that are not negotiable

Each of these is a place where the obvious C++ spelling is measurably wrong. All are pinned by a
test that goes red if someone "fixes" them.

- **A calendar vector can only carry the INSTANT, and one wall clock a year does not survive
  that.** Every sweep builds times as `midnight_ET + timedelta(seconds=n)`, which on the
  spring-forward Sunday constructs the 02:00 hour -- a wall clock that does not exist. Python
  does not object and answers from those fields; the instant written down renders as 03:00, and
  the C++ answers from that. Neither is wrong and the reference disagrees with itself on a
  re-read. `gen_golden.et_real()` drops them and prints the count. It hid 170 real-looking
  `gapcal` mismatches, and it had been silently vacuous in `varcal` -- where both readings give
  phi = 0.0, so those cases asserted nothing at all.

- **A sweep can pin a rule without testing it.** `pricing/hourly`'s two `** 0.5` sites passed a
  sqrt-for-pow mutation on the first structured grid: the two differ on ~0.086% of doubles, and
  220 valued ratios hits that about 0.2 times. The grid was widened to 20k random (now,
  settlement) pairs, which catches it 3/20,440 and 11/13,401. **When a rule below says "these
  differ on 0.086% of values", the sweep that pins it needs thousands of cases, not dozens** --
  and the only way to know is to mutate the C++ and check the suite goes red.

- **`theo.cbrt` is `pow(x, 1/3)`, not `std::cbrt`.** They differ on most inputs (27 → 3.0 vs
  3.0000000000000004). It feeds every microprice, hence every theo, hence every order.
- **`** 0.5` is `pow`, not `sqrt`** — they differ on ~0.086% of values. The rule is per-site:
  `**` → `std::pow`, `math.sqrt` → `std::sqrt`, and never simplify one into the other.
- **Python `round()` is half-to-EVEN.** Reachable: `tier_offsets` at `scale_pos == 0.25`
  evaluates `round(2.5)`, which `std::round` puts a full cent out. Use `pycompat::py_round`.
- **`round()`/`floor()`/`ceil()` return ints in Python, so there is no signed zero.** Without
  correcting for it, 459 of 50,111 fuzzed `ceil_tick` cases came back `-0.0` against `+0.0`.
- **The inner `round(_, 9)` in `_floor_tick` is load-bearing** — without it, 6 of the 99 tradeable
  cent levels land a full tick low.
- **`sorted` is stable and ties are the common case** (29 of 31 keys tie on a symmetric strike
  grid). `std::stable_sort` everywhere; `min(key=)` → `std::min_element` is fine.
- **Tuple sorts are lexicographic over ALL elements** (`atmvol.combos`), not on the first.
- **`skew.atm_vol`'s outward walk is ordered by DISTANCE IN PRICE, not by index.** It used to be
  a set literal, and this port emulated CPython's hash order (ascending by `x & 7`) exactly and
  correctly. Upstream then fixed the underlying bug -- the grid is 5-wide near the money and up to
  200-wide in the tails, so equidistant *indices* are not equidistant *strikes* -- and the faithful
  emulation became the wrong answer. A port can be stale by being too faithful.
- **JSON numbers must go through `strtod`.** A hand-rolled accumulator loses ulps, and they land
  in `varcal.phi` → `var_left` → theta → R → the required edge.
- **GCC constant-folds libm with MPFR**, which need not match glibc at runtime (folded `cbrt(27)`
  differs by an ulp). No literal-argument transcendentals except `sqrt`.
- **`MISSING` is `std::optional`, never NaN.** `theo.clamp` is `min(1, max(0, x))`, which turns a
  NaN into 0.0 and would silently price a market the reference declined to price.
- **Dict insertion order reaches the wire** via `orders.py` → batch chunking. Objects and desired
  ladders keep insertion order.

- **Python 3.12's `sum()` is compensated (Neumaier), not a left fold.** Every contract and
  dollar total that the reference computes with `sum()` uses `PySum`; a plain loop broke 1,148
  move_scale cases and thousands of order-value checks.
- **numpy is its own arithmetic.** `np.log` on this AVX-512 box is Intel SVML (up to 39 ulp from
  glibc on real bars), `np.sum` is pairwise from 0.0, OpenBLAS `ddot` uses FMA. `rvol/npcompat`
  reproduces all three; `np::dot` refuses lengths it has not been verified at.
- **libcurl silently re-sends a request that dies on a reused connection -- POST and DELETE
  included.** That is a double-sent order. `net::HttpClient` blocks the retry in
  `CURLOPT_PREREQFUNCTION`; the retry decision stays with the client, as in the reference.
- **The index-age clock is `int(datetime.now(utc).timestamp() * 1e9)`**, float seconds from
  microseconds, truncated -- not the nanosecond clock (`run04::py_timestamp_ns`).
- **Log lines print Python `repr`, not JSON**, wherever the reference formats a dict or list with
  an f-string. One `kp::json::py_repr` for the whole tree.
- **`from_et` is zoneinfo `fold=0`**, never `mktime(tm_isdst=-1)`: glibc picked the second
  occurrence of the repeated November hour.

## Layout

`include/kp/**` public headers, `src/**` one .cpp per header (globbed per library: kp_base,
kp_pricing, kp_rvol, kp_net, kp_strategy, kp_app), `apps/<name>/main.cpp` one binary each.
`tests/unit/**` the original vector replays, `tests/port/test_<name>.cpp` one suite per ported
module (self-registering), `tools/gen_golden.py` + `tools/golden/gen_<name>.py` the dumpers that
drive the pinned Python, `tools/replay/` the parity sessions, the Python driver and the diff.
`include/kp/config_gen.hpp` is generated (`make config`); secrets never enter a header -- they are
read from `.env.*` under `--kalshi-root` at runtime, as config.py does.

Vectors are regenerated by `make vectors`, not committed -- generation is deterministic, and a
committed set could outlive the source it describes. Each `.vec` header carries a hash of the
Python module it came from.
